# Methods and source notes

## Data and strategy

The strategy and simulator build on Alex’s archived crypto prediction-market prototype. This release retains the fair-value formula and the buy-signal logic from that handoff. It retains the base fill model's 50 bps relative price slippage, competition rule, and partial fill rule. The new runner uses explicit, fixed settings and independent random streams for markets and fills. No license was selected for this release.

Each snapshot draws an asset, current spot price, time remaining, volatility, and momentum. Fair value applies a normal CDF to the spot/reference difference with a momentum adjustment and time-scaled volatility. Quotes are generated by perturbing model fair values. Every 35th snapshot may have a synthetic 1–3 cent ask injected. The entry rule requires a model-price difference of at least 5 percentage points and checks cheap tails first.

Settlement adds a fresh zero-mean Gaussian shock to the current distance from the reference, using the same volatility and time scale. Positive terminal distances pay UP. Other outcomes pay DOWN, including ties under this demo convention. The settlement generator shares assumptions with the forecast model and therefore offers no independent calibration test.

## Execution scenarios

| Assumption | Quoted | Base | Higher costs |
| --- | ---: | ---: | ---: |
| Miss probability for model edge ≥ 8 percentage points | 0% | 50% | 50% |
| Chance of filling half the requested size after surviving competition | 0% | 20% | 20% |
| Relative slippage on filled buys, capped at a $0.99 fill price | 0 bps | 50 bps | 100 bps |
| Flat simulated entry fee per contract | $0 | $0.002 | $0.010 |

These are experimental settings. The flat fees and random fill rules are illustrative assumptions. The base and higher-cost scenarios reuse the same execution draws. All scenarios start with $100 of simulated cash. The ledger limits each market-side position to one contract and clips fills to available cash after fees. Each winner pays $1 per filled contract and closes the market. P&L is final cash minus starting cash, which reconciles to payout minus quoted cost, realized slippage, and fees.

Order fill rate divides buy signals with any executed quantity by all buy signals. Quantity fill rate divides executed contracts by requested contracts across all buy signals. No-signal snapshots appear in the CSV and are outside both denominators.

## Verification

Local verification used Python 3.12.14. The 11 tests cover timestamp alignment, holdout isolation, API pagination, validation and deduplication, deterministic output, protection of previous runs, position and cash limits, missed fills, winning and losing settlement, duplicate settlement rejection, and P&L reconciliation. The GitHub Actions workflow is bundled for Python 3.11 and 3.13. The workflow has not run on GitHub.
